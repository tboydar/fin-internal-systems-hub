- **劇本 B**：CRM 廠商交付延遲又被退件。在廠商頁按「退件」與「核定」，劇本會跟著走，最後留下決策紀錄 DEC-110。

- **3D**：點機櫃開資料卡，按「注入故障」，受影響的樓層會換色，所有頁面的數字一起變。按「重播月結日」：影子跟著時間移動，入夜後只剩機房亮著，紙片集中在 ERP 那幾個機櫃。
- **3D 的三個比例尺**：標題旁邊切「全台」，看三個機房與 8 處據點；按「演練：總行機房停擺」，把時間點從「當下」按到「3 天」，看哪些系統先在備援中心接手、簽呈為什麼拖到最後。切「海外」，把時間軸拉到 23 點：台北天黑了，紐約是週一上午十點，正好撞上夜間批次。
- **權限矩陣**：用系統管理員登入，把「核准發版與變更」勾給內部工程師，上面立刻出現職責分離衝突。

## 可能被問到

**資料是真的嗎？**
全部是虛構的，由固定種子產生，每次還原結果相同。機構、廠商與人名都查過公司登記、GLEIF、Wikidata 與維基百科，沒有同名。

**那些句子是 AI 寫的嗎？**
不是。是規則從資料組出來的，所以工程師看到的「37 筆」與人資看到的「37 位」一定是同一個數字。這個網站不呼叫任何模型。

**為什麼不用前端框架？**
大部分的頁面是表格，原生 TypeScript 就夠。流程圖用 xyflow、3D 用 three，兩個都是進到那一頁才下載。
