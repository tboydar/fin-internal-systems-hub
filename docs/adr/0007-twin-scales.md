# ADR 0007：3D 做成三個比例尺，共用一條時間軸

- 狀態：已採用
- 日期：2026-11-24

## 背景

3D 原本只有一棟總行（ADR 0006）。它回答得了「哪個系統出事、哪層樓受影響」，回答不了另外三種問題：

- **多點**：系統不全在總行。CRM 放在廠商的機房；有備援的系統在異地各有一套待命的環境。
- **跨區域**：8 處營業據點分在北中南三區，它們連不連得上、手上壓了幾件簽呈，總行的剖面上只有一排一模一樣的小房子。
- **跨時區**：假設這家機構有海外據點，總行的「夜間批次」對紐約來說是上午十點。

另外，原本能操作的只有「點機櫃」。

## 決定

**同一個 3D 引擎放三個模型，一次看一個，像事務所同一個案子做的三個比例尺。**

| 比例尺 | 模型                                                  | 回答的問題                               |
| ------ | ----------------------------------------------------- | ---------------------------------------- |
| 總行   | 剖開的總行（`three/model.ts`）                        | 哪個系統出事，哪個單位受影響             |
| 全台   | 疊板做的台灣、三個機房、8 處據點（`three/island.ts`） | 東西放在哪，停一個機房會怎樣             |
| 海外   | 時區桌（`three/zones.ts`）                            | 各地現在幾點，總行的批次撞到誰的上班時間 |

三個比例尺共用同一條時間軸、同一份故障、同一個演練。換比例尺只是換一個模型上桌，狀態不會重算成另一套。

**為什麼海外不做地球。** 地球一次只看得到半邊，而這裡要比的正是地球兩邊的據點（台北與紐約差 13 小時）。攤平成一張桌子，24 格各是一個時區，所有據點與時差一眼看完。格子的深淺是當地的白天或晚上，前緣的深色短條是當地的上班時段；時間往前走，它們一格一格往左移。

**為什麼全台是橫躺的。** 鏡頭從西邊看過來，北在左、南在右。據點都在西部平原，這樣它們朝著觀看的人，不會被山擋住；橫的島也比較吃得滿橫的畫面。位置是示意：海岸線只取了 29 個點，靠太近的據點會被推開，城市往內陸收了一點（不然房子有一半掛在海上）。

**時差不寫死。** 每個海外據點存的是時區名稱（`America/New_York`），差幾小時由瀏覽器的時區資料庫算（`core/sites.ts` 的 `tzOffsetMin`）。紐約夏天與冬天跟台北的時差不一樣，寫死的數字每年會錯兩次。有測試守著 11 月與 7 月兩個時間點。

**演練不改資料。** 「總行機房停擺」跟「如果它停了」是同一種東西：只是換一份模型來畫。每個系統有一個復原時間目標（RTO），演練的時間點就是這些目標排出來的；停擺後第幾小時哪些系統已經在備援中心接手，完全由 RTO 推出來（`core/drill.ts`）。演練要講的一句話是：ERP 四小時就回來，但簽呈系統只有每日備份、要三天，這三天每層樓都還是受影響。

**3D 與 2D 還是同一份。** 新增的 `sitesModel()` 吃的是 `twinModel()` 的結果，所以時間、故障與演練一定一致。每個比例尺在右邊都有一張同樣內容的表；沒有 WebGL 時，左邊就是那張表。

**互動。**

- 滑過或選取一樣東西，跟它無關的小紙片退成淺灰。選 CRM，就只剩 CRM 的往來還有顏色。
- 樓層可以點：只列那個單位的介面，它每天在用的系統腳下多一圈。
- 總行旁邊的小房子可以點：換到全台，並且選好那一處據點。
- 標籤是按鈕，Tab 進得去，方向鍵在同一種標籤之間移動，再按一次同一個是取消。
- 選了什麼都寫在網址上（`view`、`focus`、`floor`、`site`、`region`、`drill`），可以直接貼給別人。

**狀態標記換成正對鏡頭的平面形狀。** 全台與海外的鏡頭抬得比較高，立體的三角錐從上面看會變形。平面的圓、三角、方塊跟 2D 頁面上的標記是同一套。

**擠在一起的標籤掛成旗子。** 台北、板橋、桃園在模型上只差幾十個像素。標籤從兩邊往中間放，每個由低到高找位置，同一個高度先試置中，再試掛在引線的右邊或左邊；不能壓到別的標籤與引線，也不能擋住還沒放的標籤要走的那一直線。

## 代價

- **延遲載入的那一包變大**：約 157 kB → 約 180 kB（gzip）。多的是另外兩個模型、把輪廓長出厚度要用的 `ExtrudeGeometry`，以及另外兩個比例尺的面板。
- **首屏的 JS**：82.8 kB → 87.7 kB（上限 90 kB）。多的是機房與海外據點的資料、演練，以及比例尺切換。另外兩個比例尺的面板（`ui/twinScales.ts`）跟 3D 放在同一包延遲載入。
- **打包的一個坑**：延遲載入的那一包如果直接 import 首屏的 UI 模組（`ui/dom.ts`、`ui/widgets.ts`），打包工具會把首屏拆成好幾個檔，壓縮之後是 91 kB，超過上限。所以那些小工具由面板借給它（`ctx.ui`），不直接 import。這條規則寫在 `twinScales.ts` 開頭。
- **新增的資料全部是編的**：三個機房的位置、每個系統的備援做法與 RTO／RPO、六個海外據點的人數與件數、資訊處的一般支援時段（08:00–20:00）。城市的經緯度與時區名稱是真的。
- **各地只算週一到週五 09:00–18:00**，當地的假日沒有算進來。
- **據點的狀態每一處都一樣**：它們用的是同一批總行的系統，模型裡沒有「某一處據點自己的線路斷了」這種事。
- **換比例尺是直接切換**，沒有鏡頭拉遠拉近的過場。

## 怎麼守住

- `tests/unit/sites.test.ts`：時差、各地的時鐘與上班與否、批次重疊、區域小計等於據點加總、演練的每個時間點、營業日跨 26 小時。
- `tests/e2e/smoke.e2e.ts`：三個比例尺切換與標籤數量、據點標籤互不重疊、點樓層與方向鍵、重播到 23 點時紐約的資料卡、演練從頭走到尾、沒有 WebGL 時另外兩個比例尺也有表格。
- `scripts/check-bundle.ts`：首屏不能超過 90 kB，也不能出現 three。
