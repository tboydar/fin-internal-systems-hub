# ADR 0004：3D 與 2D 讀同一份狀態

- 狀態：已採用
- 日期：2026-11-24

## 背景

3D 總行不能只是擺好看的。它要跟架構圖講同一件事：哪個系統有問題、哪條介面在跑、如果它停了哪幾層樓受影響。
如果 3D 自己算一套，遲早會跟 2D 的頁面對不起來。

## 決定

- 所有狀態在一個 store（`src/core/store.ts`）。頁面與 3D 都只讀它，改資料只有 `store.update()` 一個入口。
- 3D 要畫什麼，由一個不碰 three 的純函式算出來：`twinModel(state, hour, probe)`（`src/core/twin.ts`）。
  它用的就是 2D 頁面用的那些函式（`ifaceStatus`、`systemHealth`、`impactOf`）。
- `src/three/twin.ts` 只負責把這份模型畫出來。旁邊的清單、時間軸下面的長條，還有沒有 WebGL 時的表格，讀的是同一份模型。
- 劇本（`src/core/scenario.ts`）是一串改狀態的步驟。頁面與 3D 不需要知道現在在演哪一齣，照常讀狀態就會同步變化。
- 選了哪個系統放在網址的查詢參數（`focus`），所以架構圖與 3D 可以互跳，重新整理也還在。

## 代價

時間軸拉到哪個小時是頁面自己的狀態，沒有進 store，也沒有進網址。換頁再回來會回到「現在」。

## 怎麼守住

- `tests/unit/twin.test.ts`：模型裡每個機櫃、每條介面的狀態，等於 2D 用的函式算出來的結果；注入故障後受影響的樓層等於 `impactOf()` 的結果。
- `tests/e2e/smoke.e2e.ts`：在 3D 注入故障，架構圖與總覽的數字一起變；關掉 WebGL，劇本 A 照樣走得完。
